# 모델 사다리로 나눠 하기

메인 모델은 팀장이다. 직접 많이 읽지 않고, 나누고 확인하고 보고한다. 단계 기준은 전역 규칙 "모델 사다리"를 따른다.

## 1. 나누기 (시작 전에 표로 보여 준다)

할 일을 서로 독립적인 조각으로 나누고, 조각마다 가장 낮은 맞는 단계를 고른다.

| 단계 | 부르는 법 | 맡길 일 |
|---|---|---|
| 하이쿠 | Agent `subagent_type: "haiku-helper"` (읽기만이면 `"Explore"`) | 찾기, 훑어 요약, 로그·출력 요약, 기계적 일괄 수정, 명령 결과 확인 |
| 소넷 | Agent `model: "sonnet"` | 여러 파일 읽고 정리, 평범한 코드 수정·글 초안, 단순 테스트 실패 원인 |
| 오퍼스 | Agent `model: "opus"` | 설계, 원인 분석, 여러 파일에 걸친 수정, 계산 로직 |
| 페이블 | Agent `subagent_type: "fable-expert"` | 돈·보안·인증·데이터 이전 코드 검토(처음부터), 두 번 실패한 버그, 큰 변경 최종 검토 |

사용자에게 이렇게 보여 주고 바로 시작한다(승인을 기다리지 않는다. 사용자가 고치라고 하면 고친다):

| # | 조각 | 단계 | 이유 |
|---|---|---|---|

- 짧은 파일 1~3개·명령 하나로 끝나는 조각은 "메인 직접"으로 둔다. 맡기는 비용이 더 크다.
- 사용자에게 묻거나 최종 판단하는 일은 조각으로 만들지 않는다. 메인 몫이다.

## 2. 맡기기

- 서로 상관없는 조각은 한 메시지에 여러 Agent 호출로 동시에 보낸다.
- 지시문에 넣을 것: 목표, 볼 파일·폴더 경로, 하지 말 것(지우기, `.env`, 범위 밖 수정), 돌려받을 형식("핵심만 N줄", "경로:줄", 표).
- 결과는 요약만 받는다. 원문을 통째로 돌려달라고 하지 않는다.

## 3. 확인하고 올리기

- 결과를 그대로 믿지 않는다. 숫자·경로·주장은 짧게 직접 확인한다(파일 한 줄, 테스트 한 번).
- 실패면 한 단계 위로 다시 맡긴다. 실패 = 에이전트가 자기 단계를 넘는다고 보고 / 결과가 틀림 / 테스트·출력 확인 통과 못 함.
- 올릴 때 앞 단계가 한 것과 실패 이유를 같이 넘긴다. 같은 단계에 같은 지시를 다시 보내지 않는다.

## 4. 보고

1. 결론과 결과
2. 조각별로 누가 했는지 한 줄씩(올린 조각은 "하이쿠→소넷" 처럼)
3. 확인하지 못한 것과 위험
